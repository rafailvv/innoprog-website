# Устранение показа мобильного макета перед настольным

## Причина

App начинает SSR с мобильного дерева. Страницы взрослых курсов при этом уже имели `isReady=true`, а лоадер вообще отсутствовал. Дополнительно сохранённый флаг повторного посещения мог снимать прикрытие до проверки текущего viewport. При переходе на настольное дерево его динамический модуль может ещё загружаться.

Воспроизведение до исправления: локальная production-сборка, Chromium 1440 px, Python и Data Science — по четыре кадра с открытым мобильным содержимым.

## Исправление

- Лоадер присутствует в начале серверного HTML, перед содержимым, включая взрослые курсы.
- На экранах от 768 px CSS прикрывает мобильное SSR-дерево независимо от его исходной готовности. У уже готового мобильного курса сохраняется немедленный показ.
- Снятие прикрытия и флаг повторного визита требуют совпадения типа и масштаба viewport; готовность мобильного дерева не переносится на ещё не загруженный desktop-модуль.
- На текущей версии дерева ожидается появление H1. Для App запрещено раскрытие пустого содержимого по истечении прежнего аварийного таймаута. Настоящее содержимое раскрывается сразу после появления, без ожидания картинок/шрифтов и без нового минимального времени лоадера.
- Логотип прикрытия курсов загружается lazy с низким приоритетом; прежний высокий приоритет первого экрана не меняется.
- При отключённом JavaScript noscript-стиль в head убирает прикрытие, сохраняя читаемый SSR.

Дизайн, тексты, программы, формы, API, цены и навигационные действия не меняются. Другие сервисы APP/IDE/Chat не затрагиваются.

## Приёмка до выпуска

- `npm run test:ci`: 39 файлов, 390 тестов, production build, contracts, «Сведения», SEO всех 47 URL — PASS.
- Девять новых SSR-контрактов проверяют наличие прикрытия перед содержимым всех взрослых направлений; отдельный тест проверяет позднее появление H1 после таймаута без ожидания изображения.
- 30 браузерных сценариев: главная, девять курсов, тарифы, отзывы, о нас, детский раздел и детский Python на 390/1440 px. Ноль открытых кадров неправильного макета, ноль открытых пустых кадров, ноль ошибок JavaScript.
- 14 дополнительных сценариев на границе 767/768 px — те же нулевые результаты.
- JavaScript искусственно задерживался на четыре секунды для каждого запроса: первый и повторный вход на настольный Python. Правильное содержимое появилось примерно на восьмой секунде, до этого прикрытие сохранялось; ошибочных и пустых открытых кадров нет.
- Отключённый JavaScript: H1 доступен, прикрытие `display:none`.
- Скриншоты Python взрослых и детей на 390/1440 px после стабилизации совпадают с исходными пиксель в пиксель.

Новые сетевые зависимости, ожидание всех ресурсов и дополнительные искусственные задержки не добавлены. Это устранение ошибочного раннего показа; проценты ускорения или абсолютная неизменность времени на любой сети не заявляются.

## Артефакты и выпуск

В ecosystem: `workspace/reports/20261019-viewport-loader/` — baseline, покадровые проверки, slow/no-JS, итоговые тесты и подтверждение ревизии после выпуска; `workspace/artifacts/20261019-viewport-loader/` — снимки. React SSR сохраняет одинаковый server snapshot для первого клиентского рендера: https://react.dev/reference/react/useSyncExternalStore#adding-support-for-server-rendering . Исправление не меняет эту модель гидратации.
