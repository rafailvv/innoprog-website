# Безопасное ускорение: 15 октября 2026

Исходный коммит: `d02f3631dc2978512e4bacd615539609b4689192`.

## Подтверждённые причины и решения

1. **JavaScript главной на взрослых курсах.** `App.tsx` статически импортировал обе большие адаптивные версии главной (по ~148 KiB исходного TSX каждая), хотя курс их не рендерит. Обе переведены на `next/dynamic` с SSR по уже используемому в приложении шаблону курсов. SSR не выключен; главная остаётся в серверном HTML. Проверка production HTML и размера чанков выполняется после общей сборки. Размер исходного TSX не равен экономии переданного JS.

2. **CAPTCHA загружалась без попытки отправки.** Общий wrapper монтировал `InvisibleSmartCaptcha` сразу после hydration даже на посещении без формы. Теперь библиотечный виджет монтируется при первом `requestToken()`. Promise создаётся до монтирования и ждёт реальный token; библиотека 2.9.1 выполняет challenge только после готовности script/widget. Ни одна форма не отправляет заявку без token, серверная защита не меняется. Аналитика и согласия сохранены. Точный сетевой выигрыш зависит от кэша и сети и измеряется отдельно; уменьшение не заявлено по размеру исходников.

3. **Сдвиг cookie-уведомления.** Ранее эффект позиционирования запускался после видимого paint и ожидал завершения home loader. Теперь layout effect рассчитывает положение до первого видимого paint, независимо от loaderReady. Существующее правило обхода CTA сохранено. Если динамический home chunk ещё не готов при переходе с курса, локальный MutationObserver ждёт CTA только внутри home canvas и отключается после появления. Resize/scroll обработчики и очистка сохранены.

## Ошибки CAPTCHA и ограничения

- Пока script/widget загружается, запрос остаётся pending, а повторный submit не создаёт второй challenge.
- Network error самого challenge и закрытие окна завершают promise ошибкой, последующая попытка разрешена.
- Срок ожидания остаётся 120 секунд; timeout не отправляет заявку и предлагает повторить либо обновить страницу.
- У vendor loader 2.9.1 есть существующий кэш `startLoading`, который не сбрасывается после ошибки загрузки captcha.js. Этот пакет не переписан: JS/script failure теперь явно запоминается, повтор не висит, взрослые и детские формы предлагают обновить страницу. Это честный reload, а не обещание автоматического восстановления недоступного внешнего script.
- Реальные заявки не отправлялись; unit tests имитируют vendor callbacks и API, поэтому не заменяют production browser/network smoke.

## Локальная проверка

- 8 wrapper tests: отсутствие виджета до request, pending first load → token, double request, network/close retry, script failure → немедленная ошибка при retry, timeout → retry, unmount → reject/late callback.
- 12 детских form tests, включая отсутствие API-запроса при CAPTCHA script failure и понятный reload текст.
- 6 cookie tests, включая синхронную начальную позицию, позднее появление CTA и cleanup до появления CTA.
- `vitest`: 26 tests PASS в этих трёх файлах; server-navigation ещё 5 PASS до финального извлечения observer helper.
- `tsc --noEmit --incremental false` PASS на финальном патче; финальный общий build/CI выполняет основной агент.
- Обязательная интеграционная приёмка: серверный HTML главной, cold course→home navigation без cookie consent, размеры desktop/mobile, формы с mandatory token, отсутствие CAPTCHA script на обычном посещении.
